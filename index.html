一、职业目标设定

从我的个人经历出发，明确“想成为谁、要做什么、为什么”。

1. 切入点：兴趣的起点与持续投入

我对“开发”和“教育”两条线的兴趣，最早可以追溯到高二：当时我开始尝试写博客。
记录学习、分享经验的过程中，我逐渐发现：一方面，搭建网页、调整样式、写功能会让我产生强烈的掌控感；
另一方面，把内容写清楚、让别人看懂并受到帮助，会带来持续的正反馈。

这段经历让我意识到：我并不只是喜欢“写代码”，我更在意代码最终能否帮助学习者更高效地理解、练习与复盘。

2. 目标定位：教育方向的全栈开发者

结合兴趣与能力结构，我将职业目标定位为：教育方向的全栈开发者。
具体来说，我希望在未来 3–5 年内，能够独立完成从需求分析、产品设计到前后端实现、上线维护的闭环，
聚焦在“学习工具/教育资源平台”等教育技术场景。

3. 为什么选择这个方向：专业背景与技能积累的交叉点

选择该方向主要有三点原因：

  1. 专业支撑：教育技术学的学习能帮助我理解教学目标、学习过程与评价方式，从而更懂“怎么做才有效”。
  2. 技术积累：长期自学并实践编程，让我具备把想法快速做成原型并迭代的能力。
  3. 结合优势：我更擅长把复杂知识拆成可执行的步骤，并通过产品化方式沉淀为可复用的学习资源。

目标画像

  • 岗位方向：教育行业研发 / edtech 产品技术岗 / 教育平台开发
  • 产出形式：学习工具、题库/资源平台、教学辅助系统
  • 工作风格：持续迭代、数据驱动、小步快跑

核心能力

  • 前端：页面实现、交互、组件化、工程化
  • 后端：基本接口设计、数据存储、部署与维护（逐步强化）
  • 教育：教学设计、学习者分析、评价与反馈机制

二、实现目标的具体行动和成效

用“行动—过程—结果”来呈现能力成长，并尽量可验证、可量化。

行动 1：自学前端并维护个人博客

我从高中开始自学前端相关知识，并把博客作为长期练习场。
一开始我使用现成主题完成基础搭建，随后逐步尝试：改样式、优化阅读体验、增加页面功能、调整构建与部署流程。
这种“边做边学”的方式，使我能在真实需求中持续打磨技能。

成效与证据
  • 持续迭代：博客页面结构、样式与功能会随着学习进度不断调整与重构。
  • 可追溯记录：GitHub 提交记录可体现真实的学习过程与改动轨迹。
  • 内容沉淀：以笔记/总结/工具页的形式，把知识整理成可复用的学习资源。

行动 2：其他项目实践

除了博客，我也做过一些其他项目，有前端的记事本，终端模拟等，程序方面例如小游戏、脚本工具等。
它们让我更熟悉一个项目从想法到落地的关键环节：需求拆分、任务排期、功能实现、调试修复、打包发布与用户反馈。
同时也让我逐步接触到“全栈”所涉及的不同技术要素。

代表性项目：安师生活地图（校园生活分享地图）

2026 年暑假，我发起并主导开发了一个真正面向“使用者”的项目：安师生活地图 （map.florance.top）。
它要解决的问题很具体：新生和同学常常在群里反复问“哪家店好吃”“哪里能修电脑”“周末去哪玩”，
这些经验散落在聊天记录里，问一次、答一次，然后就被刷过去了。
于是我把它们整理成一张可以按分类筛选、按地点查看的校园生活地图，让信息被沉淀下来、被反复使用。

项目档案

  • 项目定位 校园生活 / 美食与娱乐分享地图（已上线）
  • 线上地址 map.florance.top
  • 开源情况 GPLv3 开源，75 次提交 / 3 位贡献者
  • 我的角色 项目发起人 / 主导开发（需求、架构、前后端、上线运维）
  • 团队分工 我主导开发 + 成员负责审核 / 美工 / 信息采集 / 辅助开发
Vite React 高德地图 JS API Supabase PostgreSQL Edge Functions RLS 行级权限 Storage Cloudflare Turnstile Vercel SMTP 通知

这个项目也是我第一次把“全栈”完整地走了一遍：
前端负责地图、分类筛选、详情页与投稿表单；后端用 Supabase 承担数据库、鉴权、对象存储与 Edge Function；
部署在 Vercel 并绑定自有域名。真正花时间的并不是把页面画出来，而是让信息值得信任。

小团队与分工

这件事最后不是我一个人做完的。为了让它能持续运转，我发起组建了一个小团队： 由我主导开发，其他成员分别负责审核、美工、信息采集与辅助开发。

  • 我（主导开发）：定需求与产品方向、设计数据库与接口、实现前端、负责部署上线与迭代节奏，并把任务拆给成员。
  • 审核：处理每天新增的待审投稿，判断信息是否真实、是否适合公开展示。
  • 美工：负责界面视觉与配图素材，让内容更好读、更愿意被点开。
  • 信息采集：线下收集校园内外的地点信息、图片与说明，保证地图上一直有内容可看。
  • 辅助开发：参与部分功能实现与问题修复，补齐我顾不上的细节。

分工之后我才意识到：审核、美工、信息采集这些环节，恰恰是纯技术视角最容易忽略、却直接决定产品能否长期运转的部分。
也正因为把“谁负责什么”提前说清楚了，我才有精力回到最需要我的地方——架构与迭代。

关键实现

  • 投稿入口：匿名投稿需先通过 Cloudflare Turnstile 人机校验，并限制每日投稿次数。
  • 审核机制：投稿先进入待审队列，管理员审核通过后才会出现在公开地图上。
  • 图片流转：投稿图片先存进私有存储，审核通过时再迁移到公开存储并回填到地点记录。
  • 权限边界：公开地图的数据库策略只允许读取“已通过”的地点，其余数据不可见。

工程细节

  • 用数据库迁移脚本（001–007）管理表结构演进，而不是手工改表。
  • 配置了 CSP、HSTS 等安全响应头，并按最小权限原则设定策略。
  • 新投稿写入成功后，自动给管理员发通知邮件，减少审核延迟。
  • 用 Git 分支与 Pull Request 组织协作，而不是直接往主干推代码。

  • 已真实上线：拥有独立域名与 HTTPS，任何人打开链接就能直接使用，不再停留在本地 Demo。
  • 团队协作：从“一个人写代码”变成带一个小团队——我主导开发，成员分别负责审核、美工、信息采集与辅助开发，靠提前说清的分工把日常维护跑了起来。
  • 开源协作：以 GPLv3 协议公开源码，累计 75 次提交、3 位代码贡献者（审核、美工、信息采集这类非代码角色不计入其中），并合并了同学提交的改进 PR。
  • 内容质量：靠“人机校验 + 每日限额 + 管理员审核”三道机制过滤垃圾信息，让地图上的内容可信、可用。
  • 反馈闭环：上线后按真实使用情况持续迭代——补充分类筛选、优化移动端安全区布局、保持管理员登录状态等。

三、职业目标和行动的动态调整

职业规划不是一次性决定，而是“实践—反馈—调整”的循环。

1. 早期想法：先把开发能力做扎实

早期我更关注技术本身：把前端学会、把项目做出来、把能力提升。
但那时对“要做什么行业/服务什么场景”并没有明确答案。

2. 上大学后的变化：在教育场景里找到结合点

进入大学后，通过教育学课程与教学场景的观察，我发现开发与教育可以形成互补：
技术提供效率与工具，教育理论保证目标与方法。
这使我的目标逐渐从“做开发”调整为“做能落地的教育产品与学习工具”。

3. 一次真实的“实践—反馈—调整”：安师生活地图

暑假做的安师生活地图，是我第一次把作品交到真实使用者手里，也第一次完整经历了“实践—反馈—调整”的循环：
刚起步时我的想法很简单——把地点标到地图上就行；真正上线后才发现，决定它有没有用的不是功能数量，而是信息可不可信、手机上顺不顺手。
于是我主动把重心从“再多做一个功能”调回“把投稿与审核这条链路做扎实”，并针对真实反馈陆续调整了分类筛选、移动端布局与管理员入口。
也是在这个阶段，我组建了一个小团队并承担起主导开发的角色：把审核、美工、信息采集、辅助开发分给成员，让项目从“我一个人的项目”变成一件能持续运转的事。

这段经历让我调整了四点认知
  • 用户反馈比功能数量更重要：先让核心链路可靠，再考虑扩展。
  • “可信”是需要被设计出来的：审核流程、投稿限额、人机校验都属于产品的一部分。
  • 上线不是终点，而是拿到真实反馈、进入迭代循环的起点。
  • 一个人做不完的事要靠分工：能把事情讲清楚、让成员也能做好，本身就是一项需要练的能力。

4. 下一步计划：把博客升级为学习资源分享站

下一阶段我计划把博客从“个人记录”升级为“学习资源分享站”，例如：
上传试卷分析文档、知识点梳理、学习方法总结，并加入更适合学习的功能模块。
这既是对全栈能力的训练，也是对教育工具可行性的验证。

资源分享站（第一版）功能设想

  • 资源分类：学科/章节/难度/题型
  • 检索与标签：快速定位资料与错题
  • 上传与版本：同一资源多版本迭代
  • 评论/反馈：收集使用体验与改进点

验证方式（可评估）

  • 用户数：同学/学习群体的试用人数
  • 留存率：是否愿意持续使用与回访
  • 有效性：是否减少整理时间、提升复习效率

5. 更长远的调整：根据实践反馈持续迭代方向

更长远来看，我会持续用项目实践来验证方向：
如果“资源分享站”的价值被证明（有人愿意用、能节省时间、能提升学习效率），我会进一步扩展到更完整的学习系统；
如果反馈显示某些功能价值不高，我也会及时收缩范围，把精力集中在最有效的模块上。

我的调整原则
  • 以学习效果与用户反馈为核心，而不是“为了炫技而开发”
  • 优先做可验证的小功能，再逐步扩展到系统
  • 持续记录复盘：每次迭代都要有明确改进点

四、总结

坚定目标，给出承诺。
